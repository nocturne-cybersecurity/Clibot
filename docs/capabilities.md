# Capabilities

## Web and language

- `browser.open_url`: opens a requested URL in a desktop browser; requires a graphical session for interactive use.
- `browser.close_application`: requests a graceful SIGTERM for supported, exactly matched desktop application processes. It requires confirmation because unsaved work may be lost, and intentionally does not close arbitrary process names.
- `web.search`: fetches public HTML search results from DuckDuckGo, with Bing fallback, and presents the best excerpt. Web search is opt-in through an explicit search request; ordinary questions, troubleshooting, and generated code do not trigger it. It requires internet but no browser; provider blocking, bot checks, or markup changes can make results unavailable. It does not read full pages or synthesize beyond the returned excerpts.
- `translation.translate`: translates up to 5000 characters through Google's public endpoint using the Python standard library, with a MyMemory fallback when Google responds HTTP 429. It needs internet; the supplied text is sent to the provider actually used.
- Model-backed interpretation is provided by `intelligence/llm_integration.py`; an available local Ollama model is detected automatically, while remote providers still require explicit configuration. Set `model.enabled` to `false` in settings or `CLIBOT_USE_LLM=false` to disable model use. Model-proposed operations still use the registered schema, validator, risk classification, and executor confirmation flow.
- `stack_exchange.search_code_examples`: searches Stack Overflow questions and returns short code blocks from attributed answers with source links when the user explicitly asks for a source search.
- `github.search_code`: searches GitHub code and returns source-linked match excerpts; GitHub requires a personal access token in `GITHUB_TOKEN`.

Registered: filesystem listing, metadata, bounded text read, name/text search, create, mkdir, copy, move, delete, hashes, disk usage, large-file lookup and ZIP/TAR archive handling; read-only system facts, local date/time, RAM, current identity/directory, journal logs, top-level disk-usage ranking and large-file scanning; safe arithmetic, powers, roots, trigonometric/log functions; process listing, memory ranking, inspection, and confirmed PID-targeted termination; network interface/route/DNS inspection, local address lookup, listening ports, resolution, TCP checks, ping, traceroute and observational diagnostics; systemd status/list/logs and confirmed service changes.

Filesystem APIs are also available as direct Python functions. Network interface/routes prefer `ip` with `/proc` fallbacks; listening ports use `ss` or `/proc`; logs require `journalctl`; service operations require `systemctl`. Other registered functions include focused CPU/GPU information, RDAP/WHOIS lookup without a local `whois` executable, Python script/argv execution, desktop browser/app launch and supported-app closing, safe local file opening, Nmap availability, authorized scans, DNS lookup, and evidence-based report writing. Development supports local Git init and clone, status, branches, diff, log, stash, add, commit, pull, push, checkout, merge, and rebase. Pull, push, checkout, merge, and rebase require confirmation; init, clone, add, and commit follow the normal configured risk policy. Local time/date and system inspection work without internet. Asking to create a text file without a name starts a short follow-up flow; unrelated requests cancel stale clarifications. Routine operations need no confirmation by default; high-impact and destructive operations do. Recent requests and bounded result/error summaries are retained in session memory and `/history`, and `/forget` clears that memory. Package-manager search/install, storage, cloud, databases, Docker/Kubernetes, traffic capture and sandboxing are not complete interactive workflows. Scanner execution requires an explicit authorization declaration, confirmation, and installed Nmap. RDAP, translation, and web search require internet. Root, graphical session, local binaries, and DNS availability may be required for specific functions.
