# Capabilities

## Web and language

- `browser.open_url`: opens a requested URL in a desktop browser; requires a graphical session for interactive use.
- `web.search`: fetches public HTML search results from DuckDuckGo, with Bing fallback, and presents one short result excerpt without displaying URLs. It requires internet but no browser; provider blocking, bot checks, or markup changes can make results unavailable. It does not read full pages or synthesize beyond the returned excerpt.
- `translation.translate`: translates up to 5000 characters through Google's public endpoint using the Python standard library, with a MyMemory fallback when Google responds HTTP 429. It needs internet; the supplied text is sent to the provider actually used.
- Optional model-backed interpretation is provided by `intelligence/llm_integration.py`; Ollama is local and optional. Model-proposed operations still use the registered schema, validator, risk classification, and executor confirmation flow.

Registered: filesystem listing, metadata, bounded text read, name/text search, create, mkdir, copy, move, delete, hashes, disk usage, large-file lookup and ZIP/TAR archive handling; read-only system facts, local date/time, RAM, current identity/directory and journal logs; safe arithmetic, powers, roots, trigonometric/log functions; process listing, memory ranking, inspection, and confirmed PID-targeted termination; network interface/route/DNS inspection, local address lookup, listening ports, resolution, TCP checks and observational diagnostics; systemd status/list/logs and confirmed service changes.

Filesystem APIs are also available as direct Python functions. Network interface/routes prefer `ip` with `/proc` fallbacks; listening ports use `ss` or `/proc`; logs require `journalctl`; service operations require `systemctl`. Other registered functions include focused CPU/GPU information, RDAP/WHOIS lookup without a local `whois` executable, Python script/argv execution, desktop browser/app launch, safe local file opening, Nmap availability, authorized scans, DNS lookup, and evidence-based report writing. Local time/date and system inspection work without internet. Asking to create a text file without a name starts a short follow-up flow; unrelated requests cancel stale clarifications. Routine operations need no confirmation by default; high-impact and destructive operations do. Recent requests and bounded result/error summaries are retained in session memory and `/history`, and `/forget` clears that memory. Package-manager search/install, storage, cloud, databases, Docker/Kubernetes, traffic capture and sandboxing are not complete interactive workflows. Scanner execution requires an explicit authorization declaration, confirmation, and installed Nmap. RDAP, translation, and web search require internet. Root, graphical session, local binaries, and DNS availability may be required for specific functions.
