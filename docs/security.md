# Security model and limitations

LLMAH is a local helper, not a security boundary or sandbox. The parser only maps recognized phrases to fixed registered operations; unknown requests do not become shell commands. Structured command helpers default to `shell=False`. Validation covers the complete operation plan and refuses selected protected root paths. File writes avoid silent overwrite; destructive deletions require confirmation. ZIP/TAR extraction checks for traversal.

The default CLI policy does not interrupt routine/read-only/moderate actions. High-impact and destructive actions require interactive confirmation and are denied on EOF. The categories are configured in `config/policies.yaml`; commands, package installation, service changes, security scans, and destructive file actions remain in the high/destructive categories. This is a convenience policy, not a sandbox: review the operation description before approving consequential actions. There is no silent sudo or password storage. Networking diagnosis is read-only. Nmap helper requires an explicit authorization flag and confirmation but cannot establish legal authority. Redaction patterns are best-effort and cannot find every secret. Do not send sensitive logs to reports or treat local output as trusted. Persistent audit/history facilities exist as helpers but are not yet wired into the CLI.

Web search, GitHub/Stack Exchange lookup, RDAP lookup, and translation are outbound network actions. General factual questions may send their text as a search query; code lookup sends its query to Stack Overflow or GitHub. Avoid sending secrets or private data. Search results are untrusted external content shown as text; they are not executed or treated as instructions. Stack Overflow code snippets retain answer attribution and source links. The optional Ollama model is contacted over localhost only and is auto-detected when available. An OpenAI-compatible provider is never selected implicitly: configuring it opts into sending unrecognized requests and a short, redacted context summary to the configured service. Model output is untrusted; operation names, arguments, dependencies, protected paths, and required confirmations are validated locally before execution. A model cannot run a tool on its own, and validation is not a sandbox.
